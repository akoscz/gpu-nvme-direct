A single CUDA thread on a consumer RTX 3090 autonomously manages NVMe I/O queues — constructing commands, writing doorbells via PTX MMIO, and polling completions — without any CPU involvement in the data path. This is the first system to demonstrate GPU-initiated NVMe I/O on commodity hardware.

Key Insight

On AMD consumer platforms (B550/Vermeer), PCIe posted writes from GPU to NVMe BAR0 succeed even though non-posted reads fail. Since NVMe doorbells only need writes, a GPU can drive the entire NVMe controller using only posted Memory Write TLPs. This asymmetry has not been documented in prior work.

Tiered P2P Approach

Tier 1 Write-Only P2P Host pinned memory. Works on AMD consumer. Implemented.
Tier 2 Patched P2P NVMe DMA to GPU VRAM. Requires tinygrad patches.
Tier 3 Native P2P All in GPU HBM. Enterprise GPUs (A100). BaM approach.

Application: LLM Inference from NVMe

For models that exceed GPU VRAM (e.g., Llama 2 70B Q6_K at 42 GB on a 24 GB GPU), weights must be streamed from storage per token. gpu-nvme-direct removes the CPU from this critical path:

Data PathBW80 Layerstok/s
mmap+memcpy1.5 GB/s35.7 s0.028
gpu-nvme-direct (Gen3)2.1 GB/s25.5 s0.039
gpu-nvme-direct (Gen4)5.0 GB/s10.7 s0.093

Combined with sub-1-bit quantization (NanoQuant), the data volume per token drops from 42 GB to ~8 GB, projecting ~0.5 tok/s at Gen4 bandwidth.
