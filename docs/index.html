A single CUDA thread on a consumer RTX 3090 autonomously manages NVMe I/O queues — constructing commands, writing doorbells via PTX MMIO, and polling completions — without any CPU involvement in the data path. This is the first system to demonstrate GPU-initiated NVMe I/O on commodity hardware.

Key Insight

On AMD consumer platforms (B450/Vermeer), PCIe posted writes from GPU to NVMe BAR0 succeed even though non-posted reads fail. Since NVMe doorbells only need writes, a GPU can drive the entire NVMe controller using only posted Memory Write TLPs. This asymmetry has not been documented in prior work.

Tiered P2P Approach

Tier 1 Write-Only P2P Host pinned memory. Works on AMD consumer. Implemented.
Tier 2 Patched P2P NVMe DMA to GPU VRAM. Requires tinygrad patches.
Tier 3 Native P2P All in GPU HBM. Enterprise GPUs (A100). BaM approach.

Total hardware cost: ~$2,000. No enterprise GPU, no PCIe switch, no custom kernel module.

Application: LLM Inference from NVMe

For models that exceed GPU VRAM (e.g., Llama 70B Q6_K at 42 GB on a 24 GB GPU), weights must be streamed from storage per token. gpu-nvme-direct removes the CPU from this critical path. Measured results from ntransformer integration:

Data PathBWtok/s
mmap+memcpy (CPU)1.5 GB/s0.03
gpu-nvme-direct (SN740)3.35 GB/s0.06
Tiered VRAM/RAM6.5 GB/s0.20
Tiered + layer skip + Q4_K_M6.5 GB/s0.50

17x improvement over CPU-mediated NVMe baseline. Combined with NanoQuant (sub-1-bit quantization), NVMe-only streaming could match tiered results without RAM caching.
